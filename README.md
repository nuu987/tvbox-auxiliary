
# TVBox Auxiliary
A JSON Formatter & Automation Helper for TVBox  
基于 https://gitee.com/tengxiaobao/tvbox-source-aggregator 二次开发，不考虑兼容性，专为容器版开发
> ⚠️ 警告：本项目**纯使用** AI 辅助开发，不推荐也不应将此项目用于生产等环境中。  
> ⚠️ 警告：本项目不提供也不存储任何影片资源与资产。
> 

## 改进功能 
1. **热重载多数配置项**：站点编辑后无须重新聚合，应用更改即可立即生效
2. **点播站点屏蔽增强**：使用正则表达式进行自动化匹配屏蔽，减少每次聚合后的人工介入操作量
3. **网页UX交互增强**：无须精确点击复选框，点击行条目的任意空白处即可勾选
4. **智能响应静态资源地址**：判断客户端访问接口时的主机地址并复用为该客户端生成动态静态资源地址
5. **优化自动聚合操作**：改进了自动聚合的定时操作体验，修正了容器的时区问题
6. **增强日志记录能力**：项目运行时将输出更多日志信息以提供给用户调查问题
7. **屏蔽直播功能**：提供一键屏蔽直播功能开关，避免臃肿化接口数据文件
8. ~~还有但是忘了……~~


## 重大变更
1. 不再支持 Cloudflare Worker 部署
2. 不推荐使用 Native 本地时运行，仅推荐 Docker 容器部署
3. 智能响应功能默认情况下不支持非局域网访问
4. 不再支持统一管理网盘类点播站点用户凭据功能，已计划完整移除
5. 不再支持 i18n
6. 不再支持多网页主题样式，仅保留亮暗两种主题
7. 不再支持 SQLite3，仅保留 Json 数据持久化
8. 不再支持站点分类接口标签
9. 等等……
  

## 用法

### Docker 部署（首选）

```
wget https://raw.githubusercontent.com/nuu987/tvbox-auxiliary/refs/heads/main/docker-compose.yml
docker compose up -d
```

### 本地运行（仅供开发）
前置依赖  
- Node.js 18+

```
cp .env.example .env
node scripts\start.js
```



## 点播接口数量上限

`MAX_DATA_SOURCES` 默认 `6`，正整数设置上限，`0` 表示无限制；无效值使用默认值。修改环境变量后重启应用或重建容器。

此限制只计接口列表中的点播配置，包含已有粘贴单仓和多仓导入的每个单仓，MacCMS 和直播独立。达到上限后禁止添加/导入；批量导入按去重并排除已有接口后的新增候选数预检，超出剩余名额则整批拒绝，不截断保存。按 URL 去重，不比较内容。

已有超限列表保留，聚合只处理前 N 条；超限行显示灰色和“暂无数据”。新聚合失败继续提供合法旧结果，实际删除接口的失效规则保持。设置为 `0` 后恢复全部接口处理。

## 接口添加与导入

“单仓添加”输入名称及完整 HTTP(S) 地址，名称留空时使用接口网址作为名称；“高级添加”支持每行一条单仓地址、每行一条多仓地址，或一份多仓 JSON，三种格式不可混合。只展开一层多仓，嵌套多仓和相对子地址会提示并跳过。新导入不支持原始单仓 JSON 或独立解密字段，密钥可放在 URL 的 `;pk;` 后。

添加时使用与聚合相同的下载、解码及重试逻辑，并与静态资源共用重试机制：总共最多 3 轮，等待间隔为 1 秒、2 秒，约 30 秒总预算；超时后不再启动下一轮。每轮保留 UA 和代理回退，因此底层 HTTP 请求数可能超过 3 次。检查至少一条可准备的点播站点后保存。合格配置从整批保存起暂存五分钟，聚合开始时有效的数据可直接复用，过期则正常下载；新接口先显示“等待聚合”。导入不会自动聚合或立即修改输出，也不代表已有成功聚合缓存。

导入最多四个并发获取；普通添加、高级导入与聚合互斥，忙时请等待完成后重试。

## 多接口 JAR 与站点保留

聚合会选择一个全局 `spider`，为依赖其他 JAR 的站点保留独立 `jar`。同 key、api 的站点仅在有效 JAR 声明也相同时合并；地址、MD5 声明或加载前缀不同则分别保留，并生成不重复的站点 key。即使文件内容相同或不同地址声明相同 MD5，也不按内容合并。

同一 JAR 地址出现不同 MD5 声明时，分别缓存并在日志和接口管理行显示提示；提示不改变接口健康或失败计数。页面提示随成功聚合更新，冲突消失后清除。项目不验证 JAR 内容是否符合 MD5，也不能从同一地址恢复上游已不存在的旧版本。

导出保留各站点的原始 JAR 地址、MD5 和加载前缀，不携带本地缓存地址或页面诊断。缓存键升级后首次聚合可能重新下载 JAR；已有屏蔽记录按旧聚合结果转换，无法确认归属的旧记录保留且不自动套用到新变体。
